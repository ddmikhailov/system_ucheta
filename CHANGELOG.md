# История версий

## Не выпущено

- **В общих перечнях — только группы с куратором**: день, дисциплина кураторов, «Свод» и выгрузки Excel учитывают только группы, на которых сейчас назначен действующий куратор (не заместитель; пользователь не отключён). Группы без куратора показываются отдельно — на вкладке «Вакантные группы» (все группы без куратора, назначение куратора оттуда же). Правило динамическое: после назначения куратора группа сама попадает в общие перечни, ничего скрывать и возвращать вручную не нужно. Отдельно `python -m scripts.hide_groups [--apply]` архивирует группы со строчной «о» в коде («ИСПо212», «РУо112», «ГДоз226д») — их нет ни в общих перечнях, ни среди вакантных; на сервере шаг выполняется после загрузки реестра.

- **Коды групп без хвоста реестра**: загрузка реестра теперь называет группы без года набора и номера подгруппы («ИИ112-26» → «ИИ112», «ИБС155.8» → «ИБС155»); группы, отличавшиеся только хвостом, считаются одной — студенты подгрупп переходят в основную, опустевшие подгруппы скрываются. Существующие группы переименовываются вместе с кураторами, историей и отметками. Файл реестра читается по названиям колонок (лишние колонки — телефон, почта и т. п. — игнорируются и в базу не попадают). Списки кураторов дополнены: отделение — третья колонка единого `curators.tsv`.

- **Журнал индивидуальной работы (этап 5, часть «а»)**: заметки в карточке студента получили виды «Вызов родителей», «Совет профилактики», «Визит домой», **дату события** (можно задним числом, не в будущем) и необязательное **«Вернуться к вопросу»** с отметками «Выполнено» / «Вернуть в работу»; раздел карточки теперь называется «Индивидуальная работа и заметки». Новый раздел **«Индивидуальная работа»** (куратору — его группы, зав. отделением и тьютору — отделение, остальным — все группы): по выбранной группе показаны студенты с серией неуважительных пропусков (по порогу из настроек) и те, с кем уже ведётся работа — сколько записей, дата последней, ближайший срок возврата к вопросу (просроченный выделен). Если серия пропусков есть, а записей об индивидуальной работе за 14 дней нет — «нужна работа», такие строки идут первыми. Автору заметки в колокольчик приходит напоминание, когда наступил срок «вернуться к вопросу» (одно на студента и дату; клик открывает карточку студента). Миграция `n5c6d7e8f9a0`.

- **Многошаговые задачи (этап 4, часть «г»)**: в карточке задачи — «Добавить следующий шаг» (у автора задачи и администратора, только после последнего шага). Шаг — это обычная задача со своим названием, формой, сроком и проверяющим; охват и группы он берёт у предыдущего шага. Для каждой группы следующий шаг **закрыт**, пока её предыдущий шаг не принят (по умолчанию) либо не сдан (на выбор при создании шага). При открытии куратору приходит уведомление «Открыт следующий шаг …»; пока шаг закрыт, он виден в «Моих задачах» как «Ждёт предыдущий шаг», его нельзя заполнять, по нему нет напоминаний и просрочки. В списке задач видно «(шаг N из M)», в карточке — цепочка шагов со ссылками. Задача без проверки открывает следующий шаг сразу при отправке; возврат уже открытый шаг не закрывает. Группа, добавленная позже, получает шаг вместе с предыдущим. Удалять шаги нужно с последнего. Миграция `m4b5c6d7e8f9`.

- **Периодические задачи (этап 4, часть «в»)**: во вкладке «Задачи → Шаблоны» у шаблона настраивается расписание — «каждый месяц» (в выбранное число) или «каждый семестр» (то же число сентября и февраля) и срок «через N дней» после запуска. Очередная задача создаётся сама, когда после даты запуска кто-нибудь откроет платформу (отдельного планировщика нет, как и у напоминаний); к названию добавляется период («— Октябрь 2026», «— осенний семестр 2026»). Если платформу не открывали несколько месяцев, создаётся одна актуальная задача, а не все пропущенные. Задача создаётся от имени автора шаблона и с его правами на охват (зав. отделением — только своё отделение); если автор уже не может создавать задачи (отключён, роль сменилась), запуск пропускается и причина видна в списке шаблонов. Расписание меняет автор или администратор. Двойной запуск исключён (условное занятие запуска + уникальность «шаблон + период»). Удаление шаблона не трогает созданные задачи. Миграция `l3a4b5c6d7e8`.

- **Шаблоны задач (этап 4, часть «б»)**: в карточке задачи — «Сохранить как шаблон» (название по умолчанию — название задачи). В форме «+ Новая задача» появляется выбор «Из шаблона: …»: он заполняет всю форму (название, описание, режим сбора, проверяющего, поля вместе со связью с досье, охват), **кроме срока** — его выбирают заново; после этого форму можно подправить и создать задачу. Шаблоны общие для всех, кто создаёт задачи (администратор, воспитательный отдел, зав. отделением, тьютор); сохранить можно любую задачу, к которой есть доступ; удалить шаблон — автор или администратор (созданные по нему задачи не меняются). Охват зав. отделения и тьютора при запуске по-прежнему ограничивается их отделением. Миграция `k2f3a4b5c6d7` (таблица `task_templates`).

- **Задачи наполняют досье (этап 4, часть «а»)**: в конструкторе задачи («по каждому студенту» и «по выбранным») у поля формы появился выбор «В досье: …» — телефон, e-mail, мессенджер, адреса, дата рождения, финансирование и новое поле **«Дополнительное образование»** (текст или множественный выбор — например, «Кружки»). Что происходит: куратору форма открывается **уже заполненной** текущими данными из досье (сохранённые им ответы приоритетнее); после **окончательной приёмки** (последней ступени проверки, либо сразу при отправке в задаче без проверки) ответы записываются в досье студентов, **пустые ответы ничего не стирают**; в карточке студента появляется заметка «Данные досье обновлены из задачи №… : Телефон, …» и запись в журнале аудита (сами значения туда не попадают). Возвращённый ответ в досье не пишется. Длина ответа проверяется по ограничению поля досье уже при сохранении черновика. **Особые данные (соц. статус, здоровье, учёт) к задачам привязать нельзя** — они шифруются и видны узкому кругу, а ответы по задаче видны шире. Миграция `j1e2f3a4b5c6` (колонка `additional_education`); в импорте досье из Excel новая колонка не добавлена, чтобы не ломать выданные ранее шаблоны.

- **Напоминания о сроках после изменения срока задачи**: если срок продлили (или перенесли) уже после напоминания, новые напоминания не приходили вообще, а в колокольчике оставалось устаревшее «срок был …». Теперь при смене срока прежние напоминания о сроках по задаче убираются, и они приходят заново к новой дате. Напоминание «ждёт проверки» не затрагивается.

- **Защита загрузки досье из Excel от «архивных бомб»**: файл до 5 МБ мог распаковаться в гигабайты и исчерпать память сервера. Теперь слишком раздутые архивы (больше 50 МБ после распаковки, более 200 внутренних файлов, листы на миллионы строк) отклоняются с понятным сообщением; обычные файлы по шаблону работают как прежде.

- **Доступность**: поле пароля на странице входа читалось программами экранного доступа как «ПарольПоказать», а кнопка «Показать» не доставалась клавишей Tab — исправлено; ссылки в таблицах (имена студентов, «Период» и т. п.) больше не сдвинуты на несколько пикселей относительно заголовков столбцов.

- **В задаче видно, кто и когда проверил**: в карточке задачи у куратора и проверяющего — «Ход проверки» (отправлено, возвращено, принято: кто и когда; при двухступенчатой проверке — на какой ступени; «принято автоматически» для задач без проверки) и строка «Принято …, проверил(а): …»; в матрице групп у автора и администрации — новый столбец «Проверка» (кто принял или вернул и когда, либо когда отправлено на проверку). - **Социальный паспорт группы (этап 2)**: в меню появился раздел «Соц. паспорт» — сводка из досье по группам (студентов, несовершеннолетних, бюджет/договор, без представителей, с незаполненным досье, а также сироты, опека, инвалидность, ОВЗ, многодетные, малоимущие, ПДН/КДН, внутренний учёт, стипендия/соцвыплаты) с итогом и фильтром по отделению; по клику — паспорт группы с поимённым списком по каждой категории. Выгрузка в Excel: сводка (только числа) и паспорт группы (с листом поимённых списков). Куратор видит свои группы, зав. отделением и тьютор — своё отделение, администратор, воспитательный отдел, соц. педагог и психолог — весь колледж. Поимённый паспорт и выгрузка группы пишутся в журнал просмотров досье (на каждого студента из категорий), сводка — в журнал аудита. Цифры по категориям полны ровно настолько, насколько заполнено досье (показывается число студентов с пустым досье); без ключа шифрования особые категории не показываются.

- **Загрузка досье из Excel**: на странице «Студенты» — «Загрузить досье из Excel…». Шаблон скачивается из платформы (в нём уже вписаны студенты доступных вам групп — группа и ФИО, без каких-либо данных о них), заполняются нужные колонки (контакты, адреса, дата рождения, бюджет/договор, два представителя, особые данные), затем файл проверяется: предпросмотр показывает ошибки по строкам (группа/студент не найдены, неверная дата или да/нет, чужое отделение, нет ключа шифрования для особых полей), и записываются только строки без ошибок. Пустая ячейка — «не менять», повторная загрузка безопасна, в журнале аудита видно только какие поля менялись. Зав. отделением и тьютор загружают только по своему отделению. Файл до 5 МБ, до 5000 строк.

- **Зав. отделением = тьютор по правам в своём отделении**: у обоих полный доступ ко всему своему отделению — создание и правка групп, студентов (с досье) и пользователей (кураторы, заместители, соц. педагоги, психологи; зав. отделением может назначать ещё и другого зав. отделением), назначения на группы, исключения календаря для групп своего отделения (вкладка «Календарь» появилась и у них), витрины, экспорт. Чужое отделение, отделения как таковые, общий календарь и коды отметок остаются за администратором и воспитательным отделом; администраторов и тьюторов создаёт только администратор.

- **Тьютор — полный доступ в границах своего отделения** (раньше — ко всему колледжу, как администратор). Тьютор закреплён за отделением (обязательно) и в нём видит и правит всё: группы (журнал, создание, архив), студентов, их досье, включая особые данные и журнал просмотров, кураторов, заместителей, соц. педагогов и психологов (учётки, пароли, назначение на группы), витрины и экспорт — но только по своему отделению. Не может: создавать и править отделения, общие справочники (коды отметок, календарь), создавать/менять администраторов, тьюторов и зав. отделением. Группу насовсем (с историей посещаемости) тьютор удалить может — только в своём отделении, с вводом кода группы; зав. отделением — нет. **Существующим тьюторам нужно проставить отделение** («Пользователи» → профиль), без него доступ закрыт (403 «не задано отделение»).

- **Роли «Социальный педагог» и «Педагог-психолог»**: видят и ведут досье (включая особые данные) студентов **всех** групп колледжа, смотрят все группы и витрины по всему колледжу — только на чтение. Отмечать посещаемость, менять структуру, пользователей, справочники, смотреть журнал просмотров досье и «Дисциплину кураторов» они не могут; права у них по всему колледжу, но, как и кураторы, они закреплены за отделением (обязательно при создании), поэтому зав. отделением может назначить своего специалиста куратором/заместителем группы своего отделения. Появилась страница «Студенты» — поиск по ФИО/группе (она же стартовая у этих ролей, доступна и администрации). **Они же могут вести свои группы**: куратором человек становится назначением на группу, поэтому соц. педагога и психолога можно назначить куратором/заместителем групп («Группы» → назначить) — в своих группах они отмечают посещаемость, в остальных остаются наблюдателями; «Мои группы» появляется в меню, когда назначение есть. Новые роли заводятся при запуске автоматически; назначает их администратор в «Пользователях».

- **Досье студента (этап 1, первая часть)**: в карточке студента появился блок «Досье» — контакты (телефон, e-mail, мессенджер, адреса, дата рождения, бюджет/договор), законные представители (один основной), заметки куратора (беседа, звонок, инцидент, договорённость; удалить может автор или администратор) и **особые данные** (сирота/опека, инвалидность, ОВЗ, многодетная/малоимущая семья, ПДН/КДН, стипендия, здоровье). Особые данные хранятся в БД только зашифрованными (Fernet) — нужен `DOSSIER_ENCRYPTION_KEY`; без него эти поля недоступны, остальное работает. Доступ — как к карточке: куратор/заместитель своих групп, зав. отделением своего отделения, воспитательный отдел, администратор, тьютор. Каждое открытие досье пишется в журнал просмотров (его видят администратор и тьютор), в журнале аудита фиксируется только какие поля менялись, без значений. Миграция `g8b9c0d1e2f3` создаёт 4 таблицы. Импорт из Excel, роли «соц. педагог» и «психолог» — в следующих частях этапа.
- **Хвосты ревью (этап 0)**: воспитательный отдел больше не может править и удалять группы и студентов через API (в интерфейсе у него и не было такой возможности); зав. отделением не может перенести пользователя в другое отделение через смену роли; IP клиента для лимита входа берётся из `X-Forwarded-For` по доверенному прокси (`TRUSTED_PROXY_COUNT`, по умолчанию 1), а не из подделываемой первой записи; диапазон дат в календаре и «сегодня» больше не сдвигаются на день из-за UTC (с 00:00 до 03:00 по Москве); «Все присутствуют» спрашивает подтверждение, если отмечены отсутствующие.

- **Кураторы отделения списком**: `python -m scripts.import_curators curators_Кибер.tsv Кибер [--apply]` по списку «ФИО — группа» заводит кураторов (роль куратор, без пароля, логин `фамилия.инициал`) и назначает их на группы; код группы ищется точно или как «код-ГГ» («ИБС115» → «ИБС115-26»), неоднозначная или отсутствующая группа останавливает загрузку целиком, группы с уже назначенным куратором не меняются. На сервере — разово `IMPORT_CURATORS_ON_START=true` и файл `curators_<Отделение>.tsv` рядом с выгрузками импорта.

- **Загрузка реестра контингента**: `python -m scripts.import_registry реестр.xlsx [--apply]` приводит группы и студентов всех отделений к выгрузке реестра. Отделение определяется по адресу площадки (Диджитал, Моссовет, Датахаб, Техно, Кибер, АртТех — недостающие создаются); группы со старым кодом без года («ИИ112») переименовываются в код реестра («ИИ112-26») вместе с кураторами и историей; студенты сопоставляются по группе и ФИО, новые создаются, переведённые между группами получают новое членство, статус «академ» берётся из реестра, а **отсутствующие в реестре удаляются полностью** — вместе с отметками посещаемости и периодами отсутствия (необратимо), ФИО в журнале аудита затирается; группы без студентов скрываются. Кураторов и их назначения скрипт не трогает; без `--apply` ничего не пишет. На сервере включается разово `IMPORT_REGISTRY_ON_START=true` + файл `registry.xlsx` рядом с выгрузками импорта (в git его нет, даты рождения в базу не попадают).

- **Версия для передачи системному администратору**: `python tools/build_release.py` собирает архив `release/kait20-<версия>.zip` (+ контрольная сумма и инструкция `docs/install-guide.md`), в котором ровно две папки — `backend/` и `frontend/`, а собранный интерфейс уже лежит в `backend/static`. Ни файлов Docker/Amvera/CI, ни тестов, ни служебных документов в архив не попадает; сборка останавливается, если находит лишнее (запрещённые имена файлов, упоминания Docker/Amvera/контейнеров). Сам репозиторий (Docker, Amvera, git) не меняется. Для этого запуск без Docker доведён до рабочего состояния: `scripts/entrypoint.py` читает файл `.env` рядом (раньше пароль администратора из `.env` не доходил до заполнения справочников), понимает `HOST`, пустой `PORT` и запускается на Windows; зависимость `python-dotenv` закреплена в lock-файле.

- **Lock-файлы и объявленные версии**: Python-зависимости теперь закреплены полностью — `requirements.txt` и `requirements-dev.txt` стали lock-файлами со всеми пакетами (включая зависимости зависимостей) и хэшами, собираются из `requirements.in` / `requirements-dev.in`; один файл подходит и для Linux, и для Windows. Docker ставит с `--require-hashes`. Версии объявлены: `backend/pyproject.toml` (`requires-python >=3.14,<3.15`), `backend/.python-version`, `frontend/.nvmrc`, `engines` и `engine-strict` во фронтенде; `scripts/entrypoint.py` отказывается стартовать на другой версии Python. CI берёт версии из этих файлов и проверяет, что lock соответствует `.in`; `tests/test_versions.py` следит за согласованностью версий. Версии транзитивных пакетов при пересборке обновились до свежих (например, uvloop 0.23) — набор тестов и сборка образа проверены на них.
- **Запуск контейнера на Python**: `docker-entrypoint.sh` заменён на `python -m scripts.entrypoint` — тот же порядок (ожидание БД → миграции → справочники → разовый импорт при `IMPORT_ON_START=true` → uvicorn), но без shell: в проекте не осталось исполняемого кода, кроме Python и React. Шаги выполняются отдельными процессами, а в конце скрипт заменяет себя на uvicorn, который становится PID 1. Поведение для администратора прежнее. Единственное отличие: адрес БД по умолчанию теперь `localhost` (как у приложения), а не `db`, — в `docker-compose.yml` `DB_HOST` задан явно.
- **Telegram-бот удалён полностью**: бот, привязка аккаунтов («Подключить Telegram»), планировщик рассылок (напоминания кураторам и дайджесты зав. отделением, воспитательному отделу и руководству), флаг «Получает пятничный дайджест», настройки `TELEGRAM_*`, `EMBED_WORKERS`, `WEB_APP_BASE_URL` и время рассылок, зависимости `aiogram` и `APScheduler`. Миграция `f7a8b9c0d1e2` **безвозвратно** удаляет таблицы `telegram_link_tokens` и `notification_log` и поля `telegram_chat_id`, `telegram_linked_at`, `receives_leadership_digest` у пользователей. Уведомления остались только в колокольчике; прочитанные больше 90 дней назад теперь чистятся при отметке «прочитано» (раньше — ночным заданием планировщика).
- **Ссылка и запоминание фильтров «Свода»**: адресная строка всегда отражает выбранные фильтры (вкладка, период, отделение, курс, группа, пара, срез, столбцы, «только проблемные», вид) — кнопка «Копировать ссылку» открывает «Свод» у коллеги ровно с тем же отбором и точными датами. Последний выбор запоминается в браузере; быстрые периоды («7 дней», «Этот месяц») запоминаются как период, а не как конкретные даты.
- **Фильтры в «Своде»**: панель над таблицей — быстрые периоды (сегодня, вчера, 7 дней, этот и прошлый месяц) и даты, отделение, курс, группа, срез («Всего» / «К N паре» / оба) и выбор пары, выбор столбцов по кодам отметок (в том числе «только пропуски»), «только проблемные» (ниже заданного процента или не сдано), скрытие строк без данных, сортировка по клику на заголовок и кнопка «Сбросить». Период, отделение, курс, группа и пара передаются и в выгрузку Excel; столбцы, пороги и сортировка действуют только на экране.
- **Время в журнале группы и в уведомлениях**: показывалось со сдвигом на часовой пояс (сервер отдаёт время в UTC без пометки, браузер читал его как местное). Теперь строки без пометки пояса разбираются как UTC.
- **Блоки «добавить…» сверху**: формы добавления группы, студента, отделения, пользователя и исключений календаря теперь стоят над таблицей, а не под ней — внизу длинного списка их приходилось долго искать.
- **«Все присутствуют» и «Сдать день» сверху**: панель действий над списком студентов (и в кабинете куратора, и в журнале группы у администрации); внизу списка её больше нет.
- **«К какой паре пришли»**: куратор выбирает в той же панели, к какой паре группа пришла в этот день (1–8); значение сохраняется при сдаче дня и не стирается повторной сдачей без выбора пары.
- **Карточка студента**: клик по ФИО (в списке студентов и в журнале группы) открывает отдельный экран — группа, отделение, куратор и заместитель, статус обучения, даты зачисления и выбытия, посещаемость за 30 дней, последние отметки, история групп. Всё управление студентом (ФИО, перевод в другую группу, смена статуса, удаление) перенесено на карточку из таблицы.
- **Полное удаление группы**: администратор/тьютор может удалить группу навсегда вместе со студентами, отметками, сданными днями и назначениями кураторов. Перед удалением показывается, что именно исчезнет, и нужно ввести код группы. Студенты, уже переведённые из группы в другую, не удаляются.
- **Свод на экране**: во «Витринах» новая вкладка «Свод» с теми же числами, что в Excel, — по дням, за период и по группам и дням; «Всего» и «К 1 паре» отдельными строками, по каждому коду отметки свой столбец. Для администрации и воспитательного отдела доступен фильтр по отделению.
- **Посещаемость студента по месяцам**: на карточке студента — все дни месяца с отметками и листанием по месяцам (не раньше месяца зачисления), с итогами за месяц. Карточка теперь доступна всем ролям: куратор и заместитель открывают её из списка своей группы (только просмотр, по студентам своих групп), зав. отделением — по своему отделению, администрация — по всем.
- **Дисциплина куратора по дням** (только зав. отделением): клик по строке во «Витринах → Дисциплина кураторов» показывает по дням статус сдачи, время (по времени колледжа), кто сдал и пару, плюс среднее время сдачи «вовремя».
- **Свод в выгрузке Excel**: три новых листа — «Свод по дням» (дата × отделение, «всего» и «к 1 паре»), «Свод за период» (то же суммой за период, плюс строка «Все отделения») и «По группам и дням» (по каждой группе и дню, с парой). В каждой строке: численность, учтено, прибыли, отсутствуют, процент и количество по каждому коду отметки.
- **Старые отметки с основанием «PENDING/OVERDUE»**: исправлена ошибка 500 при чтении (миграция приводит такие значения к «не требуется»).

Разблокировка после неудачных попыток входа — тоже прямо из админки.
- **Полное управление списками**: группы, студенты и кураторы теперь редактируются, архивируются и удаляются на месте. Удаление из архива безопасно — если есть история (посещаемость, назначения), запись либо не удаляется физически (группы), либо обезличивается с сохранением статистики (студенты, пользователи). Куратора можно снять с группы без потери истории назначения.
- **Журнал группы для администрации**: у admin/edu_department — по всему колледжу, у зав. отделением — в своём отделении. Любая группа, любой день, полное право правки, видно, кто и когда внёс каждую отметку.
- **Правки задним числом**: куратор может отредактировать посещаемость за любой прошедший день (было — только вчера). Если правка отстоит от занятия больше чем на 48 часов, зав. отделением получает уведомление.
- **Внутриплатформенные уведомления**: колокольчик в шапке — пока единственный канал, раз Telegram скрыт из интерфейса (сам бот и планировщик остаются на сервере, включаются настройкой).
- **Приказ/справка** у кодов отметок стали необязательным дополнением без контроля дедлайна — экран «Контроль оснований» убран, поле осталось.
