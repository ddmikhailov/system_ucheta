Цифровой куратор (КАИТ №20) — обновление до версии 3.6.0

Кому: системному администратору сервера колледжа и администратору платформы.
Откуда: с версии 3.5.1 (с более ранних — так же, миграции применятся сами при запуске).


ЧТО НОВОГО (коротко; подробно — CHANGELOG.md)

Права и роли:
  - Воспитательный отдел закреплён за отделением и видит группы, студентов, пользователей, витрины,
    питание и задачи только своего отделения. Может выдавать временные пароли кураторам, заместителям,
    соц. педагогам и психологам своего отделения.
  - Заведующий отделением — как администратор, но в пределах своего отделения: управляет всеми
    пользователями отделения (включая тьюторов, других заведующих и воспитательный отдел), назначает им
    роли, удаляет студентов и группы отделения насовсем.
  - Полное удаление студента (отчисленного или в академ. отпуске) — вместе со всей историей. Куратор сам
    стереть студента не может: он отправляет запрос, решение принимает заведующий отделением (если его
    нет — администратор).

Для всех:
  - «Забыли пароль?» на экране входа: запрос уходит в колокольчик тем, кто может выдать этому человеку
    временный пароль. Платформа не проверяет личность — получатель убеждается сам и передаёт пароль лично.
  - Колокольчик у руководителей разделён на вкладки «Моя работа» и «Управление».
  - Сессия продлевается, пока человек работает (до 7 дней от ввода пароля). «Выйти» выходит только из
    этого браузера; «Выйти на всех устройствах» — отдельный пункт меню.
  - «Назад» возвращает на прежнее место: группа, фильтры, поиск, вкладка запоминаются в пределах вкладки браузера.
  - Кнопка «Показать» в полях смены пароля.
  - Модули «Досье», «Индивидуальная работа» и «Мой ID» включены по умолчанию.
  - «Сообщить о проблеме» в меню пользователя: сообщение с адресом страницы, версией и браузером приходит
    администраторам в колокольчик (вкладка «Управление»). Номер версии виден там же.
  - Плашка «Что нового» показывается один раз после обновления.
  - Быстрее первая загрузка и меньше запросов (страницы грузятся по требованию, счётчики меню и колокольчик —
    одним запросом, скрытая вкладка сервер не опрашивает); на телефоне крупнее текст, платформу можно
    добавить на главный экран как приложение.

Администратору платформы:
  - Профиль пользователя: активность по месяцам с выгрузкой в CSV.
  - Админка → «Отладка» (только администратор): полный журнал действий с «было/стало».

Кураторам:
  - Журнал дня не теряет несданные отметки: черновик хранится во вкладке браузера и восстанавливается после
    F5, истечения сессии или ухода со страницы; при уходе с несданными отметками платформа переспрашивает.
  - «Группа риска» — теперь только по пропускам без уважительной причины (больше 40 % дней). Новый статус
    «Восполнить пропуски» — для уважительных пропусков (без практики и ИУП посещаемость ниже 85 %);
    куратор сам закрывает его с комментарием на вкладке «Студенты» группы.
  - Длительное отсутствие (больничный, приказ) можно изменить и удалить.
  - Счётчик в журнале дня: «Отсутствуют: N, опоздали: M» (опоздавшие больше не считаются отсутствующими).
  - Нумерация студентов в журнале и списках.
  - Меню пользователя → «Подставлять отметки прошлого дня»: включено, как раньше; можно выключить.

Изменения для сервера:
  - Миграции БД: 5 новых (x5g6h7i8j9k0, y6h7i8j9k0l1, z9k0l1m2n3o4, z7c1m2p3n4s5, r1a2b3c4d5e6) — новые
    таблицы password_reset_requests, student_deletion_requests, absence_compensations, колонки
    users.carry_over_marks, users.seen_release и mark_codes.no_compensation, индекс audit_log по объекту.
    Применяются сами при запуске (scripts.entrypoint).
  - Новых Python-пакетов нет, но requirements.txt всё равно установить (шаг 3 ниже).
  - Новые параметры .env — необязательные, значения по умолчанию подходят:
      SESSION_RENEW_BEFORE_MINUTES=120   SESSION_MAX_DAYS=7
      RISK_UNEXCUSED_PERCENT=40          COMPENSATION_REOPEN_DAYS=3
      AUDIT_RETENTION_DAYS=365           SENTRY_DSN= (пусто — сбор ошибок выключен)
    RISK_ATTENDANCE_PERCENT (85) теперь порог статуса «Восполнить пропуски», а не группы риска.
    Если ENABLED_MODULES в .env задан явно, досье и индивидуальная работа включатся только после
    добавления dossier и individual_work в список.
  - Журнал действий и журнал просмотров досье теперь хранятся не больше AUDIT_RETENTION_DAYS дней (решение
    колледжа — год). Старые записи платформа удаляет сама раз в сутки, первый раз — при первом открытии
    платформы после обновления. Подробно: kait20-nadezhnost.txt.
  - Смена ключа шифрования досье без потери данных — kait20-klyuch-dosie.txt (делать не обязательно).
  - Требования прежние: Python 3.12 (допустимы 3.13/3.14), MySQL 8.1.0+.


ПЕРЕД ОБНОВЛЕНИЕМ

  1. Проверить целостность архива (файл .sha256 лежит рядом с архивом):
       Linux:    sha256sum -c kait20-3.6.0.zip.sha256
       Windows:  Get-FileHash .\kait20-3.6.0.zip -Algorithm SHA256   (сравнить с содержимым .sha256)
  2. Резервная копия БД обязательна: в этой версии есть миграции. Эту копию сохранить отдельно и надолго:
     в ней остаются записи журнала действий старше года, которые 3.6.0 удалит при первом открытии.
  3. Выбрать время, когда кураторы не отмечают посещаемость: перерыв в работе — 1–2 минуты.
  4. Предупредить кураторов: после обновления сдать начатые дни заново не придётся, но несданные
     отметки, введённые ДО обновления, черновиком не сохранятся (черновик появляется только в 3.6.0).


ОБНОВЛЕНИЕ — LINUX (пути и имена — как в инструкции администратору, раздел 5.4)

  # 1. резервная копия БД и копия текущей версии
  sudo -u kait20 /opt/kait20/kait20-backup.sh
  sudo rm -rf /opt/kait20/backend.prev
  sudo cp -a /opt/kait20/backend /opt/kait20/backend.prev

  # 2. распаковать новую версию
  cd /tmp && sha256sum -c kait20-3.6.0.zip.sha256
  rm -rf /tmp/kait20-new && unzip -q kait20-3.6.0.zip -d /tmp/kait20-new

  # 3. остановить, заменить код (сохранив .env и .venv), проверить зависимости, запустить
  sudo systemctl stop kait20
  sudo rsync -a --exclude .env --exclude .venv /tmp/kait20-new/backend/ /opt/kait20/backend/
  sudo chown -R kait20:kait20 /opt/kait20/backend
  cd /opt/kait20/backend && sudo -u kait20 .venv/bin/pip install --require-hashes -r requirements.txt
  sudo systemctl start kait20

  # 4. проверка
  curl -s http://127.0.0.1:8000/health                 # -> {"status":"ok"}
  grep '^version' /opt/kait20/backend/pyproject.toml   # -> version = "3.6.0"
  journalctl -u kait20 -n 80 --no-pager                # строки "Running upgrade ... -> r1a2b3c4d5e6", без ошибок
  cd /opt/kait20/backend && sudo -u kait20 .venv/bin/alembic current   # -> r1a2b3c4d5e6 (head)


ОБНОВЛЕНИЕ — WINDOWS (инструкция администратору, раздел 10.4)

  # 1. резервная копия БД (задача kait20-backup) и копия текущей версии
  Start-ScheduledTask kait20-backup
  robocopy C:\kait20\backend C:\kait20\backend.prev /MIR /XD .venv

  # 2. распаковать новую версию
  Expand-Archive .\kait20-3.6.0.zip -DestinationPath C:\Temp\kait20-new -Force

  # 3. остановить, заменить код (сохранив .env и .venv), проверить зависимости, запустить
  Stop-ScheduledTask kait20
  robocopy C:\Temp\kait20-new\backend C:\kait20\backend /E /XD .venv /XF .env
  C:\kait20\backend\.venv\Scripts\pip install --require-hashes -r C:\kait20\backend\requirements.txt
  Start-ScheduledTask kait20

  # 4. проверка
  Invoke-WebRequest http://127.0.0.1:8000/health -UseBasicParsing     # -> {"status":"ok"}
  Select-String '^version' C:\kait20\backend\pyproject.toml           # -> version = "3.6.0"
  Get-Content C:\kait20\logs\kait20.log -Tail 80                      # "Running upgrade ... -> r1a2b3c4d5e6", без ошибок
  cd C:\kait20\backend; .venv\Scripts\alembic current                 # -> r1a2b3c4d5e6 (head)


СРАЗУ ПОСЛЕ ОБНОВЛЕНИЯ — АДМИНИСТРАТОРУ ПЛАТФОРМЫ (обязательно)

  1. Закрепить каждого сотрудника воспитательного отдела за отделением:
     Админка → Пользователи → сотрудник → «Управление» → Отделение → сохранить.
     Пока отделение пустое, сотрудник видит «У вас не задано отделение» и не видит групп.
  2. Проверить, что у каждого отделения есть активный заведующий: ему приходят запросы на правку прошлых
     дней, на удаление студентов и на восстановление пароля. Если заведующего нет — эти запросы уходят
     администраторам.
  3. Если ENABLED_MODULES в .env задан явно — решить, добавлять ли dossier и individual_work (см. выше).


ЧТО СКАЗАТЬ ПОЛЬЗОВАТЕЛЯМ

  Заведующим отделением: вы управляете всеми пользователями и студентами своего отделения, как
  администратор. Запросы кураторов (удаление студента, правка прошлого дня, восстановление пароля)
  приходят в колокольчик, вкладка «Управление».

  Воспитательному отделу: теперь вы работаете в пределах своего отделения; можете выдавать временные
  пароли кураторам своего отделения.

  Кураторам: «Забыли пароль?» на экране входа; новые статусы «Группа риска» и «Восполнить пропуски»
  (второй закрываете сами на вкладке «Студенты»); длительное отсутствие можно исправить; отметки в
  журнале больше не пропадают при F5 и истечении сессии; перенос отметок прошлого дня отключается в меню
  пользователя; «Выйти» больше не выкидывает на телефоне — для этого есть «Выйти на всех устройствах».


ПРОВЕРКА В БРАУЗЕРЕ (после обновления)

  1. Войти администратором — рабочий экран открывается.
  2. Админка → Группы: есть столбец «Студентов».
  3. Выйти; на экране входа есть «Забыли пароль?». Отправить запрос на тестовый логин — у администратора
     в колокольчике, вкладка «Управление», появилось уведомление.
  4. Открыть журнал любой группы, поставить отметку, обновить страницу (F5) — отметка восстановилась
     («Восстановлены несданные отметки этого дня»). Сдать день или сбросить отметку.
  5. Витрины → «Группа риска»: есть переключатель «Группа риска / Восполнить пропуски / Все».
  6. Сверху страницы — плашка «Что нового в версии 3.6.0»; в меню под именем — «Версия 3.6.0» и
     «Сообщить о проблеме». Отправить тестовое сообщение — оно пришло администратору в колокольчик.


ОТКАТ (если что-то пошло не так)

  В 3.6.0 есть миграции, поэтому сначала откатить схему БД НОВЫМ кодом (в старом нет файлов миграций),
  потом вернуть прежнюю папку. Данные, введённые после обновления в новые таблицы (запросы на пароль и на
  удаление, закрытия «Восполнить пропуски»), при откате пропадут. Удалённые записи журнала старше года
  откат не вернёт — они есть только в резервной копии.

    Linux:    sudo systemctl stop kait20
              cd /opt/kait20/backend && sudo -u kait20 .venv/bin/alembic downgrade w4f5g6h7i8j9
              sudo rsync -a --delete --exclude .env --exclude .venv /opt/kait20/backend.prev/ /opt/kait20/backend/
              sudo systemctl start kait20
    Windows:  Stop-ScheduledTask kait20
              cd C:\kait20\backend; .venv\Scripts\alembic downgrade w4f5g6h7i8j9
              robocopy C:\kait20\backend.prev C:\kait20\backend /MIR /XD .venv /XF .env
              Start-ScheduledTask kait20

  Если alembic downgrade завершился ошибкой — восстановить БД из резервной копии, сделанной на шаге 1,
  и вернуть прежнюю папку.
