Цифровой куратор (КАИТ №20) — ключ шифрования досье (DOSSIER_ENCRYPTION_KEY)

Кому: системному администратору и ответственному за платформу.
С версии 3.6.0.


ЗАЧЕМ ЭТО ВАЖНО

Особые поля досье студента (здоровье, ОВЗ, инвалидность, сиротство, учёт ПДН/КДН, соц. статус) хранятся
в базе зашифрованными ключом DOSSIER_ENCRYPTION_KEY из файла .env.

  - Ключ потерян или заменён по ошибке — эти данные НЕ ВОССТАНОВИТЬ ничем, в том числе резервной копией базы.
  - Резервная копия базы без ключа особых полей не вернёт: ключ и копии хранятся раздельно, но оба нужны.


ГДЕ ХРАНИТЬ КЛЮЧ

  1. В файле .env на сервере (так платформа его читает).
  2. Копия — вне сервера, в двух местах: у ответственного за платформу и у администратора колледжа
     (менеджер паролей или запечатанный конверт в сейфе). Не в почте, не в мессенджере, не рядом с копиями базы.
  3. После любой замены ключа (см. ниже) обновить обе копии.

Проверка, что ключ на месте: при запуске службы в журнале НЕТ строк «DOSSIER_ENCRYPTION_KEY не задан»
и «DOSSIER_ENCRYPTION_KEY некорректен»; в карточке студента особые поля открываются.


КОГДА МЕНЯТЬ КЛЮЧ

  - ключ мог увидеть посторонний (попал в переписку, на снимок экрана, в чужие руки);
  - уволился сотрудник, у которого была копия;
  - плановая смена по правилам колледжа.
Без причины ключ менять не нужно.


КАК СМЕНИТЬ КЛЮЧ БЕЗ ПОТЕРИ ДАННЫХ

В DOSSIER_ENCRYPTION_KEY можно указать несколько ключей через запятую: первым шифруется всё новое,
читаются данные под любым из них. Порядок:

  0. Сделать резервную копию базы (kait20-backup.sh / kait20-backup.ps1) и сохранить текущий .env.

  1. Сгенерировать новый ключ (в папке backend, из виртуального окружения платформы):
       python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

  2. В .env записать НОВЫЙ ключ ПЕРВЫМ, а прежний — через запятую после него, без пробелов и кавычек:
       DOSSIER_ENCRYPTION_KEY=<новый ключ>,<прежний ключ>
     Перезапустить службу. С этого момента новые записи шифруются новым ключом, старые читаются прежним.

  3. Проверить, что все записи читаются (ничего не меняет):
       python -m scripts.rotate_dossier_key
     Ожидается «не читается ни одним ключом: 0». Если не 0 — остановиться: часть записей была зашифрована
     ещё каким-то ключом; найти его и дописать в конец списка, иначе эти записи будут потеряны.

  4. Перешифровать всё сохранённое новым ключом:
       python -m scripts.rotate_dossier_key --apply
     Повторный запуск безопасен. Дата изменения досье при этом не меняется.

  5. Убрать прежний ключ из .env (оставить только новый), перезапустить службу, открыть пару карточек
     студентов с особыми полями — они должны открываться.

  6. Обновить копии ключа вне сервера (раздел «Где хранить ключ»). Старый ключ уничтожить.

Важно: резервные копии базы, сделанные ДО шага 4, читаются только ПРЕЖНИМ ключом. Пока такие копии хранятся,
храните и прежний ключ (вместе с отметкой, к каким копиям он относится).
