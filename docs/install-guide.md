# КАИТ-20 — установка на сервер

В архиве три папки: `backend/` (Python), `deploy/` (конфигурации Apache/службы/копий и PDF-инструкция) и `frontend/` (исходники интерфейса на React).
Собранный интерфейс уже лежит в `backend/static`, поэтому **Node.js на сервере не нужен** —
он требуется только если вы захотите пересобрать интерфейс сами.

Проверьте целостность архива: SHA-256 должен совпасть с файлом `.sha256` рядом с ним.

## 1. Что установить заранее

| Что | Версия | Зачем |
|---|---|---|
| Python | **3.12, 3.13 или 3.14** (проверено на 3.12) | запуск приложения; на версии вне диапазона оно откажется стартовать |
| MySQL | 8.1 и новее (ветка 8.x; версию на сервере не обновлять), кодировка `utf8mb4`, сортировка `utf8mb4_unicode_ci` | база данных |
| Шрифт DejaVu Sans (Linux: пакет `fonts-dejavu-core`) | любая | кириллица в PDF-выгрузках; без него PDF строятся, но кириллица в них нечитаема. На Windows используется системный Arial |
| Обратный прокси с HTTPS (Apache 2.4 с модулями `proxy`, `proxy_http`, `headers`, `ssl`; подойдёт и nginx) | любой | платформа сама HTTPS не обслуживает. Готовый виртуальный хост Apache — `deploy/kait20-apache.conf` из архива (проверен) |

Исходящий доступ в интернет приложению не нужен (кроме опционального Sentry, если задан `SENTRY_DSN`).
Компилятор не нужен: все пакеты ставятся готовыми колёсами.

## 2. База данных

```sql
CREATE DATABASE kait20 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'kait20'@'localhost' IDENTIFIED BY '<пароль>';
GRANT ALL PRIVILEGES ON kait20.* TO 'kait20'@'localhost';
```

Таблицы создаются автоматически при первом запуске (миграции).

## 3. Установка

```bash
cd backend
python3.12 -m venv .venv      # или python3.13 / python3.14 — любая из поддерживаемых
.venv/bin/pip install --require-hashes -r requirements.txt     # Windows: .venv\Scripts\pip ...
cp .env.example .env                                           # и заполните, см. ниже
```

`requirements.txt` — полный список пакетов с точными версиями и хэшами; один файл для Linux и Windows.

## 4. Настройка (`backend/.env`)

Обязательно: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `JWT_SECRET`
(длинная случайная строка), `ADMIN_USERNAME`, `ADMIN_PASSWORD` (пароль первого администратора;
при первом входе его сменят). Остальные параметры описаны в `.env.example`.
Переменные окружения, заданные в системе, важнее значений из `.env`.

**Пароли (с версии 3.5.1).** Пароль пользователя платформы — от 10 символов, обязательно строчная и заглавная буква,
цифра и спецсимвол (например `! # $ % & * ?`). Нельзя: подряд идущие буквы, цифры или клавиши (`abc`, `123`, `qwer`),
один символ три раза подряд, логин или ФИО, распространённые пароли (`Password2026!`, `Qwerty…`, `Kurator…`).
Требования показываются под полем нового пароля. Временные пароли, которые выдаёт платформа, — 14 символов со
спецсимволами; передавайте их точно, с учётом регистра. Пользователь со слабым паролем, заданным до 3.5.1, при входе
обязан сменить его — это ожидаемое поведение, а не сбой.

**Какие разделы включены (`ENABLED_MODULES`).** В версии 3.5.0 платформа работает в релизном наборе: **посещаемость, задачи,
«Мой ID», питание, досье студента и индивидуальная работа**. Соц. паспорт, план группы, родительские собрания, отчёт куратора
и связанные с ними выгрузки скрыты для всех ролей — и в интерфейсе, и в API (адреса отвечают 404). Данные этих разделов,
если они были, остаются в базе. Переменную задавать **не нужно**: если её нет или она пуста, действует релизный набор.
Вернуть скрытые разделы можно значением `ENABLED_MODULES=all` в `.env` (или списком через запятую: `attendance`, `tasks`,
`my_id`, `meals`, `dossier`, `passport`, `individual_work`, `plan`, `meetings`, `reports`) и перезапуском службы.
Опечатка в имени — приложение не запустится и назовёт ошибочное значение.

`DOSSIER_ENCRYPTION_KEY` — ключ шифрования особых данных досье (здоровье, соц. статус, учёт ПДН/КДН); команда для генерации —
в `.env.example`. Пока раздел «Досье» скрыт, платформа работает и без ключа, но **задайте его сразу** и сохраните отдельно
от базы данных: при возврате раздела ранее сохранённые особые данные читаются только тем же ключом. **Ключ нельзя менять
или терять:** при потере или замене расшифровать уже сохранённые особые данные невозможно. Резервная копия базы без этого
ключа для таких данных бесполезна.

Дополнительно для запуска:

- `PORT` — порт (по умолчанию 8000);
- `HOST` — адрес прослушивания (по умолчанию `0.0.0.0`; если прокси на том же сервере — поставьте `127.0.0.1`);
- `TRUSTED_PROXY_COUNT` — сколько прокси стоит перед приложением (обычно 1), иначе лимит попыток входа
  будет считать всех пользователей одним адресом;

## 5. Запуск

```bash
cd backend
.venv/bin/python -m scripts.entrypoint
```

Скрипт сам: дожидается базы → применяет миграции → создаёт справочники и администратора →
запускает приложение. Проверка: `http://<сервер>:8000/health` отвечает 200, главная страница — интерфейс. После входа в меню нет
пунктов «Соц. паспорт», «Индивидуальная работа», «План группы» и «Отчёт куратора» (так и должно быть в релизном наборе).

**Запускайте ровно один экземпляр приложения.** Лимит попыток входа хранится в памяти процесса;
несколько экземпляров будут считать его раздельно.

Для постоянной работы запустите команду как службу (systemd, Windows-служба и т. п.) с рабочей
папкой `backend`. Полный шаблон службы — `deploy/kait20.service` (там же проверенный vhost Apache, скрипт резервного копирования,
сценарии для Windows; пошаговая инструкция в PDF — `deploy/kait20-instrukciya-administratoru.pdf`).
Минимальный шаблон для systemd; **он не проверялся на реальном сервере**, адаптируйте под себя:

```ini
[Unit]
Description=KAIT-20
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/kait20/backend
ExecStart=/opt/kait20/backend/.venv/bin/python -m scripts.entrypoint
Restart=on-failure
User=kait20

[Install]
WantedBy=multi-user.target
```

Запуск проверен: Linux (Python 3.12 — полный запуск `scripts.entrypoint` с миграциями на сервере БД; Python 3.14 — в CI; чистая установка по `requirements.txt` с хэшами) и Windows. Работа за Apache с TLS (вход, обновление страницы по прямому адресу, выгрузки) проверена; на MySQL 8.1.0 приложение запускалось только в составе тестов 8.4 — перед промышленным вводом выполните первый запуск на тестовой копии базы.
Не проверялись: оформление в службу (systemd/Windows), ARM, macOS.

## 5а. Загрузка групп, студентов и кураторов

Без обновления платформы: администратор платформы открывает «Админка → Импорт», скачивает шаблон Excel (с текущими данными),
правит и загружает — сначала предпросмотр, затем запись; ничего не удаляется. То же из консоли (из папки `backend`):
`python -m scripts.import_contingent файл.xlsx` (проверка) и `... --apply` (запись), `--issue-passwords пароли.csv` — временные пароли
новым кураторам. Подробности и порядок первичной загрузки — в PDF «Инструкция администратору», раздел 7. Windows-сервер — раздел 10 того же PDF.

## 6. Обновление версии

Остановите приложение, замените содержимое `backend/` (сохранив `.env` и `.venv`), выполните
`pip install --require-hashes -r requirements.txt`, запустите заново — миграции применятся сами.
Перед обновлением сделайте резервную копию БД (`mysqldump`).

**Обновление 3.5.0 → 3.5.1:** миграций БД, новых пакетов и новых параметров `.env` нет — достаточно заменить код и
перезапустить службу. Пошагово (Linux и Windows) и чек-лист проверки — `deploy/kait20-obnovlenie-3.5.1.txt` в архиве.

## 7. Пересборка интерфейса (необязательно)

Нужны Node.js 22.12+ и npm. В папке `frontend`: `npm ci && npm run build`, затем содержимое
`frontend/dist` скопируйте в `backend/static`.
