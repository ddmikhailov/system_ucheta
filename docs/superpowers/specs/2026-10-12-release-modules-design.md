# Релиз 3.5.0 — выключаемые модули (посещаемость, задачи, Мой ID, питание)

Дата: 2026-10-12. Статус: **черновик на проверку** (код не менялся).

## 1. Цель и рамки

К релизу от платформы требуется только: **посещаемость и её ведение (полностью), задачи, «Мой ID», питание**.
Всё остальное из интерфейса и API исчезает для **всех ролей** (набор функций у всех одинаковый, различается лишь область
видимости данных — как сейчас). Реализованный код, таблицы, миграции и сами данные **остаются** как уже сделанная работа;
возврат модулей — сменой одной переменной окружения, без правок кода.

Что сказал заказчик (дословно по смыслу):

- остаются: посещаемость, задачи, «Мой ID», питание;
- убираются: соц. паспорт, досье студента, индивидуальная работа, планы, отчёты и всё, что администрация видит по ним;
- договоры и документы (протоколы бесед, DOCX планов/отчётов/собраний) уходят вместе со своими модулями.

Решения, согласованные в чате: (1) без переменной окружения включён **релизный набор** (безопасный по умолчанию);
(2) данные досье и паспорта остаются в базе, но недоступны ни через интерфейс, ни через API (для 152-ФЗ они продолжают
храниться — удаление отдельным решением); (3) версия **3.5.0**.

## 2. Модули

| Модуль (`ENABLED_MODULES`) | Состояние в релизе | Что входит |
|---|---|---|
| `attendance` | включён, не выключается | журнал, «Мой день», «Мои группы», витрины, исправления журнала, справки/выгрузки посещаемости, карточка студента (обзор, посещаемость, история, управление), «Студенты» (поиск), админка (структура, пользователи, календарь, справочники), импорт контингента, уведомления |
| `tasks` | включён | задачи от администрации, шаблоны, проверка ответов |
| `my_id` | включён | «Мой ID» |
| `meals` | включён | питание |
| `dossier` | **выключен** | досье, представители, записи/беседы, протоколы бесед, журнал просмотров, импорт досье, вкладка «Досье» |
| `passport` | **выключен** | соц. паспорт, сводка, выгрузки (Excel/DOCX) |
| `individual_work` | **выключен** | индивидуальная работа, напоминания «вернуться к вопросу» |
| `plan` | **выключен** | план группы (`/events`), DOCX плана и протоколов мероприятий |
| `meetings` | **выключен** | родительские собрания и их протоколы |
| `reports` | **выключен** | отчёт куратора, DOCX отчёта |

Выключенные модули — те, что в таблице отмечены «выключен». Формат значения:
`ENABLED_MODULES=attendance,tasks,my_id,meals` (запятые, регистр не важен). `attendance` включён всегда, даже если не указан.
Неизвестное имя в списке — ошибка запуска (опечатка не должна молча включать/выключать модуль). Значение `all` включает всё.
**По умолчанию** (переменная не задана) = `attendance,tasks,my_id,meals`.

## 3. Backend

### 3.1 Реестр модулей
Новый `app/core/modules.py`: список имён, `enabled_modules()` (из `Settings.enabled_modules`, кэшируется как
`get_settings`), `module_enabled(name) -> bool`. Сервисы импортируют его из `core`, не из `api` (правило слоёв).

### 3.2 Роутеры
В `main.py` роутер подключается только если модуль включён:

| Роутер | Модуль |
|---|---|
| `dossier`, `dossier_import` | `dossier` |
| `passport` | `passport` |
| `individual_work` | `individual_work` |
| `events` | `plan` |
| `meetings` | `meetings` |
| `reports` | `reports` |
| `my_id` | `my_id` |
| `meals` | `meals` |
| `tasks` | `tasks` |

Остальные роутеры подключены всегда. Выключенный — это 404 и отсутствие в OpenAPI; правок в самих эндпоинтах нет.

### 3.3 Сквозные связи (закрываются условиями в сервисах/схемах)
- **Задачи ↔ досье:** `task_dossier` (привязка поля задачи к полю досье, `apply_accepted`), эндпоинт `GET /tasks/dossier-fields`,
  `dossier_field` в схемах — при выключенном `dossier`: поле не принимается (422 «привязка к досье недоступна»), `/tasks/dossier-fields`
  возвращает пустой список (а не 404: форма задач его опрашивает), `apply_accepted` ничего не пишет в досье. Уже созданные задачи
  с привязкой к досье продолжают работать как обычные: ответ принимается, в досье не пишется.
- **Задачи ↔ индивидуальная работа:** `task_service` вызывает `individual_work_service.generate_followup_reminders` — не вызывается
  при выключенном `individual_work`.
- **«Мой день»:** `my_day_service` берёт блок индивидуальной работы (`group_overview`, `NO_WORK_DAYS`) — при выключенном модуле поле
  в ответе пустое/отсутствует; блок «студенты, которым нужна запись» не формируется.
- **Карточка студента:** `student_card_service` строит список через `passport_service.rosters` — вынести общий кусок (состав группы) так,
  чтобы карточка не зависела от включённости `passport`; карточка без досье не возвращает полей досье.
- **`/students/{id}/dossier/card`** (карточка для модального окна в группе) — часть роутера `dossier`; фронтенд при выключенном
  модуле берёт карточку из `/students/{id}` (посещаемость). Точное решение уточняется в плане после чтения `StudentCardModal`.
- **Удаление студента/пользователя** (`erasure_service`, `user_profile_service`) — не меняется: чистит данные независимо от включённости.
- **Журнал действий (`audit`)**: старые записи с типами выключенных модулей остаются, интерфейс показывает их как есть.

### 3.4 `/auth/me`
В `MeResponse` добавляется `modules: list[str]` — включённые модули (контракт для фронтенда). Контрактный тест
`test_frontend_roles_contract.py` дополняется проверкой, что список имён модулей во фронтенде совпадает с `core/modules.py`.

### 3.5 Данные и безопасность
Таблицы, миграции, шифрование (`DOSSIER_ENCRYPTION_KEY`) не меняются. Ключ по-прежнему нужен и должен храниться: при возврате
модуля данные должны читаться. Новых миграций нет. Права по ролям не расширяются — только сужаются.

## 4. Frontend

- `constants/modules.ts` — зеркало имён модулей; `utils/modules.ts` — `isModuleOn(user, name)` по `user.modules`
  (если поля нет — считается «включено всё» только в тестах-заглушках; в продукте сервер поле отдаёт всегда).
- **Меню/нижняя панель** (`Layout.tsx`): пункты «Соц. паспорт», «Индивидуальная работа», «План группы», «Отчёт куратора» скрыты по модулям;
  «Мой ID», «Задачи», «Питание» — по своим. Быстрый переход (`CommandPalette`) получает уже отфильтрованный список.
- **Маршруты** (`App.tsx`): страница выключенного модуля → `Navigate to="/"`. Компоненты и страницы остаются в коде, подгрузка lazy.
- **Вкладки группы** (`CuratorGroupPage`): остаются «Журнал», «Студенты», «Питание», «Мой ID»; параметр `?tab=` выключенной вкладки
  игнорируется (открывается «Журнал»).
- **Карточка студента** (`StudentCardPage`): остаются «Обзор», «Посещаемость», «История», «Управление». Убираются вкладки «Досье»,
  «Представители», «Индивидуальная работа», KPI «Записи работы»/«Вернуться к вопросу» и загрузка `useDossier`.
- **«Мой день»**: без блока индивидуальной работы и кнопки «Записать» (`QuickNoteModal`).
- **Задачи** (`TaskCreateForm`): без выбора «записать в досье»; запрос `/tasks/dossier-fields` не нужен при выключенном модуле.
- **«Студенты»** (`StudentsSearchPage`): без `DossierImport`. `HomeRedirect` для соц. педагога/психолога ведёт туда же, куда остальных
  по их области (роли остаются, их специальная функция — досье — скрыта).
- **Админка**: вкладки остаются; всё, что про досье/паспорт, скрывается (проверить `UserProfilePage`/журнал действий).

## 5. Роли

Состав ролей и `core/roles.py` ↔ `constants/roles.ts` не меняются. Соц. педагог и психолог остаются в системе с областью «весь
колледж» и видят то же, что остальные, — посещаемость, задачи (если назначены), питание не входит в их доступ (как сейчас).
Срезы прав: строка/параметр в `tests/test_policies_matrix.py` для релизного режима не требуется (права не расширяются), но матрица
прогоняется в обоих режимах.

## 6. Тесты

Backend:
- по одному параметризованному тесту «релизный режим: все эндпоинты выключенных модулей → 404» (список маршрутов — из реальных роутеров);
- «полный режим» (`ENABLED_MODULES=all`) — существующие тесты проходят как раньше; `conftest.py` задаёт `all`, релизные тесты
  переопределяют настройку;
- `/auth/me` отдаёт `modules` в обоих режимах; неизвестное имя модуля — ошибка настроек;
- задачи: привязка к досье → 422 в релизе; ответ по старой задаче с привязкой принимается без записи в досье;
- «Мой день» без блока индивидуальной работы.

Frontend (Vitest): меню/маршруты/вкладки группы и карточки в обоих режимах; `TaskCreateForm` без выбора досье; редирект с
выключенных страниц.

Проверка в браузере: десктоп и 375 px; `npm run build`, `npx oxlint` — без замечаний.

## 9. Риски

- Пропущенная сквозная связь (модуль выключен, а данные или кнопка просачиваются): снижается тестом «все маршруты выключенных
  модулей → 404» и ручной проверкой интерфейса под каждой ролью.
- Рассинхрон имён модулей backend/frontend: контрактный тест.
- Существующие тесты предполагают полный набор: `conftest.py` явно включает `all`; релизные тесты изолированы.
